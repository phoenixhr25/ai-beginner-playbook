# 小白 AI 操作题

把真实使用 AI 工具时遇到的“这一步怎么做”，整理成第一次接触也能照着完成的中文操作指南。

这里不从概念体系讲起。每篇内容都来自一次真实卡点：先还原看到了什么，再说明原因、操作步骤、成功标志和下次如何避免。

项目同时维护一张[小白 AI 知识地图](docs/知识地图.md)。每出现一个新问题，除了回答眼前这一步，还会主动补出它依赖的前置知识、背后的核心概念，以及用户接下来最可能遇到的问题。

## 这个项目有什么不同

GitHub 上已有完整的 Codex 教程、AI 入门课程和资源导航。本项目采用另一种组织方式：

- 一个文件解决一个具体问题，搜索后可以直接进入答案；
- 真实案例与通用指南分开，避免把偶发故障写成普遍规律；
- 每篇注明验证日期、系统和适用入口，界面变化后可以追踪；
- 保留纠错记录，后续发现原判断不准确时直接修订；
- 默认使用普通用户能理解的界面名称，命令只在确实需要时出现。

调研过的相似项目及借鉴结论见[同类项目调研](docs/同类项目调研.md)。

## 内容结构

```text
ai-beginner-playbook/
├── 01-Codex/          # Codex 桌面端、项目和对话操作
├── 02-GitHub/         # Git、GitHub、仓库与推送问题
├── cases/             # 脱敏后的真实处理经过
├── data/              # 可维护的知识节点与关系
├── docs/              # 项目调研与维护说明
├── templates/         # 新问题写作模板
└── .github/           # GitHub Issue 模板
```

暂不提前建立空目录。遇到新的真实问题并形成第一篇内容时，再增加 Streamlit、文件备份等主题。

## 内容标准

每篇指南尽量回答七件事：

1. 这篇解决什么问题；
2. 当时看到了什么；
3. 为什么会这样；
4. 一步一步怎么操作；
5. 如何确认成功；
6. 哪些情况不适用；
7. 何时、在哪个系统或版本验证。

没有完成验证的内容必须标记为“待验证”。涉及账号、权限、价格和产品界面时，优先引用官方资料并记录核实日期。

## 提交一个问题

可以通过 GitHub Issues 提交问题。请描述你所在的应用、看到的文字或报错、已经做过的操作；截图前请遮住邮箱、访问令牌、文件路径中的个人信息。

详细规则见[贡献指南](CONTRIBUTING.md)，项目维护方式见[维护说明](MAINTENANCE.md)。

## 隐私边界

本仓库不保存账号密码、访问令牌、私人对话全文、个人数据或本机 Codex 会话文件。案例只保留解决问题所需的脱敏信息。
