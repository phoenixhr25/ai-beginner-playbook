# 同类项目调研

> 调研日期：2026-09-30
> 范围：GitHub 上面向 AI、Codex 和初学者的中文开源指南

## 结论

GitHub 上已经有多套按章节组织的 Codex 或 AI 入门教程，也有资源导航和完整文档网站。较少见的是从真实用户卡点出发，将一次对话提炼成“一个问题、一份可验证答案”，并持续记录界面变化和纠错过程。

因此，“小白 AI 操作题”适合占据这个位置：

> 真实问题驱动的中文 AI 工具操作手册。

它不追求覆盖所有功能，而是让读者搜索一个具体问题后，能直接完成操作并判断是否成功。

## 代表项目

| 项目 | 主要形式 | 借鉴点 | 本项目的区别 |
| --- | --- | --- | --- |
| [yuhao-xin/codex-from-zero](https://github.com/yuhao-xin/codex-from-zero) | 十章学习路线，含 FAQ、示例、贡献指南 | 清晰的阅读顺序；README 直接回答适合谁 | 本项目按真实问题检索，不要求从第一章顺序学习 |

| [geekjourneyx/awesome-codex-guide](https://github.com/geekjourneyx/awesome-codex-guide) | 官方资料、教程、工作流和排障资源导航 | 按目标提供入口；有贡献、安全与变更记录 | 本项目自己验证并编写答案，不以资源聚合为主 |
| [firstcontributions/first-contributions](https://github.com/firstcontributions/first-contributions) | 帮助初学者完成第一次开源贡献 | 新手友好的贡献路径和 Issue 机制 | 本项目吸收其低门槛贡献思想，用问题模板收集真实卡点 |

## 采用的做法

- README 首屏按“我遇到的问题”提供入口；
- 每篇独立成文，标题直接使用用户会搜索的问法；
- 用 Issue 模板收集新问题和纠错；
- 提供统一写作模板、贡献指南和维护节奏；
- 案例与通用指南分开；
- 软件界面、账号、权限等易变化信息记录验证日期。

## 暂不采用的做法

- 暂不建设 VitePress 或独立网站：当前内容量较小，GitHub 原生 Markdown 足够；
- 暂不追求“从零到精通”的完整课程：这会削弱真实问题驱动的特色；
- 暂不自动抓取所有新对话：先人工筛选，避免把未经验证的回答公开；
- 暂不复制其他仓库教程正文：只借鉴结构，并链接注明来源。

## 下一批候选问题

从物光对话中已经发现：

1. GitHub 设备登录时忘记输入验证码怎么办；
2. Streamlit 的 Deploy 按钮为什么是灰色；
3. `.git` 文件夹是什么，Finder 为什么看不到；
4. 手机导出的 JSON 如何移动到 iCloud；
5. MIT 许可证是什么意思，内容项目该选什么许可。

只有在重新核实当前界面或完成实际验证后，候选问题才升级为正式指南。
