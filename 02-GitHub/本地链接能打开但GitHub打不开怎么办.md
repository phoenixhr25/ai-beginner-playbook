# 本地链接能打开，但GitHub打不开怎么办

适用情况：Markdown里的相对链接在电脑上能打开，推到GitHub后提示找不到文件。

核实日期：2026-10-26。本文通过本地Git索引和临时文件测试验证，不涉及GitHub登录界面。

## 为什么会这样

GitHub只能显示已提交并推送到对应分支的文件。电脑上恰好存在的文件、被忽略的目录、另一个Git仓库里的文件，都不一定包含在这次提交中。

相对链接还要从“当前文章所在目录”计算。例如 `docs/说明.md` 中的 `../README.md` 指向仓库首页。

## 怎么修正

1. 找到链接的目标文件，确认大小写和相对路径准确；
2. 在仓库目录运行 `git ls-files -- 路径`，确认目标包含在Git索引中；没有输出时，再用 `git status --short` 和 `git check-ignore 路径` 查看原因；
3. 普通公开文档可以加入提交。私人文件、学习数据和另一个项目的源码，不要为修链接直接一起上传；
4. 如果目标属于独立项目，改为指向本仓库内的脱敏说明页，或已有且适合公开的项目链接；
5. 检查目标分支已经包含该文件，再打开GitHub文章验证链接。

本仓库可运行：

```bash
python3 scripts/validate_local_links.py
```

检查器对照Git索引检查Markdown中的内联链接、引用链接及图片路径。它会把“文件在本机，但不在提交中”视为错误。准备新文档时，先用 `git add` 将应公开的文件加入索引，再检查；`git add` 本身不会上传文件。

## 怎样确认成功

检查器退出成功，且链接目标实际出现在GitHub同一分支。持续集成会在文档变化时重新检查，可发现后续改名或删除目标造成的断链。

此检查不访问外部网址，也不验证页内标题锚点、权限和线上部署。网页本身打不开时，需要继续查网站的发布状态。
